# 11월 25일 · 시간 예산 비교 리허설

같은 시작 회로에서 **처음 검증된 개선이 언제 나왔는지**와 **마감 시점의 최선**을
분리하기 위해 실제 로컬 실행 로그와 클릭 가능한 오프라인 그래프를 추가했다.
기본 순서와 구조 규칙 우선 순서는 둘 다 AI 없이 실행한다. 비교 대상은 ABC
합성 레시피가 아니라 기존 A/B 변형 후보를 시도하는 순서다.

- 합성 회로 6개 × 두 순서 × 3회 = 36회, 후보 시도 270건.
  기준은 회로당 800 ms 및 최대 8회 시도. 후보별 시간 한도는 120 ms.
- 270건 모두 정확 열거와 Z3에서 동치였고, 이 중 237건이 원본 깊이 이하였다.
  나머지 33건은 동치지만 깊이 제한으로 채택할 수 없었다.
  타임아웃·마감 초과 실측 0건. 초과 응답을 점수에서 제외하는 경계는
  별도 가상 시계 테스트로 검증했다.
- AND 1개 이상 줄이는 목표에 각각 12/18회 도달
  (서로 다른 회로 4/6개씩; 같은 회로 3회는 독립 사례가 아님).
- A1은 마감 시 원본 14에서 기본 12, 구조 우선 11로 달랐다.
  A2·A3은 둘 다 목표 미도달. B1–B3은 두 순서의 마감 시 최선이 같았다.
- A1에서 첫 검증 개선 시점은 기본 약 135–194 ms, 구조 우선 약 46–54 ms.
  미리 만든 예제의 이 호스트 관측치다. 일반적인 속도 우위, 라이브 AI,
  실제 암호·채굴 성능을 입증하지 않는다.
- 동일 후보 집합에서 순서만 바꾸지만 8회 시도 예산으로 실제 방문한 후보가
  다를 수 있다. 이 차이는 회로 변환 메뉴 자체의 확장이 아니다.

## 재현

프로젝트 루트에서:

    cd dev
    PYTHONPATH=. python3 -m mdai.anytime /tmp/mdai-new-trace.json
    cd ..
    python3 dev/tools/reprove_anytime.py dev/evidence/anytime/trace.json /tmp/mdai-reproof.json
    python3 dashboard/build.py
    PYTHONPATH=dev python3 -m unittest discover -s dev/tests
    python3 -m unittest discover -s dashboard -p 'test_*.py'
    node dashboard/test.mjs

Z3 공유 라이브러리가 필요하다. 기존 원시 로그와 재검사 기록은 덮어쓰지 않는다.
재검사는 기록을 재계산하고 후보 59종을 직렬화·재파싱해서 동치를 확인한다.
당시 시계값을 독립 재현했다는 뜻은 아니며 새 실행의 타이밍이나 상태 수는
달라질 수 있다. 오프라인 파일의 요약은 JavaScript 없이도 읽을 수 있다.

## 실제 모델 비교의 다음 기준

실제 전송을 붙인 뒤 비채점 A/B 예제로 모델 ID·설정, 타임아웃 후 결과
폐기와 취소 영수증, 토큰·비용 영수증부터 확인한다. 클라이언트 연결 중단과
서버의 실제 중단·과금 여부를 분리한다. 요청 시작 / 응답 수신 / 검증 완료를
같은 단조 시계에 기록한다. 동일 사례, 시작 AIG, 목록 해시, 시도 수, 시드,
검증 한도와 사전 정의한 목표를 사용한다. 목표 미도달에 임의 시간을
채우지 않는다. 유료 호출, 랭커 학습, 최종 홀드아웃, 실제 암호·채굴은 이번
작업에서 열지 않았다. 정식 3주차 검증 상태는 여전히 부분 완료다.

## 점검 기록

일반 테스트 75개 통과(격리 조건에서만 가능한 테스트 묶음은 일반 실행에서
제외), 격리 환경에서 별도 4개 통과, 대시보드 빌더 테스트 5개 통과,
Node DOM 상호작용 검사 통과. 실제 브라우저 실행은 설치된 Chromium
런처에 실행 파일이 없어 실패했다. 휴대폰 렌더링은 확인하지 않았다.
